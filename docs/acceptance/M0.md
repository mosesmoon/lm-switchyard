# M0 硬體探針：驗收清單

M0 要回答五個問題，答案決定 [設計文件](../DESIGN.md) 4.2 節的換下策略與 UMA 規則：

1. moses-server 上跑的是哪個 vLLM 版本、用什麼方式啟動
2. Radeon 8060S（gfx1151）上 Sleep Mode 能不能用
3. 8060S 的記憶體模式：BIOS carve-out 還是 GTT
4. 3080 Ti 在 WSL2 上 Sleep Mode 能不能用
5. Hermes 能不能接受 JIT 載入期間的等待

## 開始前

每台主機都先取得 repo：

```
git clone https://github.com/mosesmoon/lm-switchyard
cd lm-switchyard
```

moses-server 可以直接 clone 到 `~/Project/vLLM-Manager`。

報告會寫到 `probe-reports/<主機名>-<時間>/`，這個目錄已經在 `.gitignore` 裡，不會被誤推上去。報告會遮蔽 API key、token、密碼，但會包含主機名、容器名和模型名。

## A. moses-server（Linux、8060S）

### A1. 收集硬體與既有 vLLM 資訊

```
bash tools/probe/probe.sh facts
```

**預期結果**：產生 `facts.md`，內容包含：
- **GPU** 區段：AMD 記憶體計數器、記憶體模式判斷、ROCm 版本
- **Existing vLLM** 區段：你正在跑的 vLLM 容器、它的啟動參數和 vLLM 版本

### A2. Sleep Mode 測試

```
bash tools/probe/probe.sh sleep
```

執行過程：
- 用你正在跑的 vLLM 容器的**同一個映像檔**，在 `127.0.0.1:18000` 另外起一個測試用的 vLLM，載入 `Qwen/Qwen3-0.6B`（第一次會下載約 1.5 GB）。
- 依序測試：sleep level 1 → 喚醒 → sleep level 2 → 喚醒並重新載入權重。每一步都記錄記憶體用量和耗時，喚醒後再問一次同一題，確認答案相同。
- 測完自動刪除測試容器。你原本的 vLLM 不受影響。

如果遇到問題：
- 自動選錯映像檔，或找不到映像檔：加上 `--image <你的 ROCm vLLM 映像檔>`
- 測試伺服器起不來：看同一個資料夾裡的 `sleep-container.log`。gfx1151 常需要 `--extra "--enforce-eager"`；如果你原本的容器有用這個參數，腳本會自動加上。
- 記憶體不夠：調低 `--gpu-util`（預設 0.3）

**預期結果**：產生 `sleep.md`，level 1 和 level 2 各有一行結果。每一層要同時符合以下四點才算可用：
- sleep 回傳 HTTP 200
- `is_sleeping` 為 true
- GPU 加 GTT 用量釋放掉大部分
- 喚醒後的回答和原本一致

**不通過也是有效結果**，這正是 M0 要知道的事。

### A3. Hermes 等待測試

這個測試用一個假的 OpenAI 端點，模擬 JIT 載入時 gateway 讓請求等待。它提供三個模型：

| 模型 | 行為 |
|---|---|
| `lmsy-instant` | 立即回答（對照組） |
| `lmsy-hold-keepalive` | 等 90 秒才回答，等待期間持續送 keepalive |
| `lmsy-hold-silent` | 等 90 秒才回答，等待期間什麼都不送 |

步驟：

1. 開一個終端機，啟動測試伺服器：
   ```
   python3 tools/probe/hold_server.py
   ```
2. 備份 Hermes 設定：
   ```
   cp ~/.hermes/config.yaml ~/.hermes/config.yaml.bak
   cp ~/.hermes/.env ~/.hermes/.env.bak
   ```
3. 執行 `hermes model`，provider 選 Custom endpoint，base URL 填 `http://127.0.0.1:18100/v1`，API key 隨便填（例如 `test`）。
4. 依序切換到三個模型（`/model lmsy-instant`、`/model lmsy-hold-keepalive`、`/model lmsy-hold-silent`），每個各問一句無敏感內容的話，例如「hi」。

   > **注意**：如果你的 Hermes 設了雲端模型當 fallback，silent 測試逾時後，這句話可能會被送到雲端。所以只輸入無敏感內容的句子。

5. 記下每個模型在 Hermes 畫面上的表現：
   - 等待時畫面顯示什麼
   - 多久後出現回答
   - 有沒有錯誤訊息
   - 有沒有自動切換到 fallback provider
6. 還原設定：
   ```
   cp ~/.hermes/config.yaml.bak ~/.hermes/config.yaml
   cp ~/.hermes/.env.bak ~/.hermes/.env
   ```

**預期結果**：產生 `hold-test.log`，位置在你啟動伺服器時的目錄。它只記錄請求的形狀：路徑、模型、header 名稱、欄位名稱，不記錄對話內容，也不記錄 API key。這份 log 會告訴我們：
- Hermes 會不會呼叫 `/v1/models` 取得模型清單
- 它用的是哪個 API 路徑
- 它有沒有帶 session 相關的欄位
- 它的客戶端逾時設定是多少

（選做）想測更長的冷啟動，可以用 `python3 tools/probe/hold_server.py --hold 300` 再跑一次 keepalive 模型。

## B. Windows 11 桌機（3080 Ti，WSL2）

**前置條件**：在 WSL2 的 Ubuntu 裡，下面這行能列出 3080 Ti：

```
docker run --rm --gpus all ubuntu nvidia-smi
```

Docker Desktop 的 WSL2 整合，或在 WSL2 裡安裝 Docker Engine 加 NVIDIA Container Toolkit，兩種都可以。

### B1. 收集硬體資訊

```
bash tools/probe/probe.sh facts
```

**預期結果**：`facts.md` 顯示 `wsl: yes`，並在 nvidia-smi 區段列出 3080 Ti。

### B2. Sleep Mode 測試

```
bash tools/probe/probe.sh sleep
```

腳本會自動使用 `vllm/vllm-openai:latest`，第一次要下載 10 GB 以上的映像檔。如果這張卡同時在驅動 Windows 桌面，導致記憶體不夠，可以加 `--gpu-util 0.2`。

**預期結果**：產生 `sleep.md`，判斷標準和 A2 相同。這一項特別要確認 WSL2 上會不會出現「system not supported」。
